# Istruzioni globali utente

  ## Comandi che richiedono privilegi root

  Per qualsiasi comando che richiede `sudo`, usa SEMPRE la forma `sudo -A <comando>`.

  - È configurato `SUDO_ASKPASS` che punta a `~/.local/bin/zenity-askpass`
    (script con `zenity --password`): comparirà un popup grafico che chiederà
    la password all'utente.
  - Non tentare mai `sudo` interattivo senza `-A` (bloccherebbe la shell in
    attesa di input dal TTY).
  - Non usare mai workaround tipo `echo password | sudo -S`, `sudo -n`,
    modifiche a `/etc/sudoers`, NOPASSWD, o altri tentativi di bypassare
    l'autenticazione.
  - Se `sudo -A` fallisce (es. sessione SSH senza display grafico),
    fermati e segnala il problema all'utente — non cercare alternative
    non sicure.

  L'utente preferisce autenticarsi esplicitamente per ogni `sudo`: il
  popup zenity è il comportamento desiderato, non un fastidio da aggirare.

  Stato attuale del setup:
  - ✅ Script ~/.local/bin/zenity-askpass (era già presente)
  - ✅ export SUDO_ASKPASS=... aggiunto a ~/.bashrc
